# 学习方法与验收

## 目标与分工

AI 负责大部分实现，学习者练习需求拆解、请求链路、数据与权限边界、代码审查、故障判断和验证。是否亲手输入样板代码不作为能力标准；是否能在没有答案提示时作出判断，需要实际提问或练习取证。

## 一次课程怎样进行

一次只设一个能验收的主目标。常规课可从 30–60 分钟开始，根据实际投入调整，不把等待工具运行算成学习任务；时间不足时选择下述 10 分钟版。

1. **恢复与回忆**：Agent 先读档案；选一道已学内容让学习者不看笔记复述，不先重讲答案。
2. **目标与预测**：解释为什么需要本课内容、它在请求链路中的位置，给出必要的新概念、行为目标与验收标准；对于用来测评的问题，先收集预测及理由，再给答案。
3. **实现与审查**：Agent 完成一个最小切片，按请求流解释关键 diff；学习者指出规则在哪一层、漏掉它会发生什么。避免把整个文件逐行朗读作为默认教学。
4. **故障与验证**：在隔离环境制造一个与目标相关的错误，先看测试是否能发现，再恢复实现并验证。只看绿色测试不足以证明它能捕获目标缺陷。
5. **迁移与反馈**：改变一个条件或业务资源，让学习者重新判断，再解释错误及边界。答不出时依次提示请求位置、涉及状态、关键代码，最后才演示。
6. **记录与交付**：分开记录工程结果、学习者实际回答、提示程度和未解决问题；更新下一课与复测项，验证并提交推送完整阶段。

提出预测题后应留出回答机会。若学习者要求直接实现、演示或跳过练习，按其要求继续，学习状态记为“已演示，未测评”；不得把 Agent 的解释记成学习者答案。无需为了实施已授权的工作重复询问许可。

10 分钟版只保留一个场景、一个预测、一段链路解释和一次反馈，不强行编码。每完成约 3 次课程安排一次短复测；优先复测曾答错或依赖提示的内容，并在后续课程再次检查。间隔与次数是可调整的执行起点，不是固定效果承诺。

## 工程证据和学习证据

| 维度 | 记录方式                                                                           | 不能推断的结论                                 |
| ---- | ---------------------------------------------------------------------------------- | ---------------------------------------------- |
| 工程 | 计划中、已实现未验证、已验证；写明单元 / HTTP / 数据库 / 浏览器 / 线上边界及日期   | 代码通过测试不等于学习者掌握，也不等于线上可用 |
| 学习 | 未测评、需提示解释、可独立预测、可在陌生场景应用；附实际回答或行为、提示程度、日期 | 听过解释、同意方案、复制答案不等于独立应用     |

一次回答只支持对应场景；阶段完成需要相关工程验收和至少一次未提前给答案的判断。记录阶段完成后仍可安排复测；复测暴露遗忘时更新当前证据，不改写旧学习日志。历史“接触过 / 理解中”保留原语义，未经复测不自动升级或降级。

当前焦点只保留少量能力项与复测项在 [学习进度](learning-progress.md)，实际课堂证据追加到 [日志](learning-log.md)。不要为每次课生成重复的计划表、评分表或大段代码副本。

## 范围与时间盒

- 同时只有一个主阶段；新主题先进入 [路线图](roadmap.md) 候选项，说明触发问题后再选入。
- 按阶段的验收标准收尾，不以把所有相关技术都实现作为结束条件。
- 每阶段超出预估课程数时先检查是否扩展了目标：缩小非关键范围，或记录为什么延长。输入校验、数据正确性、权限、密钥和适用的部署验收不能省略。
- 单纯文档整理属于指导方案维护，不算完成课程或能力测评。第一轮已经完成，后续不重复要求旧的 30 天投入时长。

## 验证边界

- Service 业务规则用单元测试；HTTP 合同测中间件、输入和响应；SQL、约束、事务与归属过滤必须有真实数据库证据。
- 根 `pnpm test` 不包含 Hono 数据库集成测试；修改 Hono 持久化行为还需 `pnpm --filter @backend-learning/hono-drizzle test:integration`。
- 当前 Hono 集成测试读取 `DATABASE_URL` 并清空三张教学表。执行前核实它指向可清理的隔离测试库，不能直接使用开发或线上业务数据；尚未建立隔离环境时先完成隔离再运行。
- 故障注入只在可恢复的本地或测试环境执行；数据库回滚实验不要求自增 ID 连续。
- 纯文档修改检查内容、命令、链接、格式和 Git diff；无需因此启动数据库、运行破坏性测试或重新部署。实现变更则运行与行为对应的必要检查。

## 阶段记录最小内容

课程日志包含日期、唯一目标、学习者预测与提示、工程验证及边界、遗留问题与下一步。指导方案维护应明确没有新增测评。格式和链接检查通过只证明文档可用，不证明业务测试通过。

主动回忆后再提供反馈的教学依据可参见 [Retrieval Practice 的反馈说明](https://www.retrievalpractice.org/feedback/)。本仓库的课程时长、复测频率和里程碑是结合当前目标制定的执行方案。
