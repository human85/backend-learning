## 已完成反馈：Request ID 与结构化日志

唯一主目标：让一次请求的 ID 能贯穿 HTTP 响应和结构化日志，支持从错误日志回到具体请求。

- 已实现：共享 `configureApp()` 在解析请求体和业务处理前注册中间件；服务端为每次请求生成 UUID，响应头 `X-Request-ID` 与请求完成 JSON 日志使用同一个编号；CORS 暴露该响应头。
- 日志只记录时间、级别、事件、请求编号、方法、路由模板、状态码、耗时；不记录原始 URL、请求体、Cookie、Token、用户标识或原始异常。异常过滤器保留显式 HTTP 4xx 合同，对未知错误返回安全 500。
- 学习证据：学习者独立答对事务回滚后重新创建 201、提交后响应丢失重放 201；正确选择公共中间件并指出每次请求应有独立编号、密码不能记录。Session 可有多个及响应头覆盖 204 由 Agent 补充，尚未独立复测。
- 当前边界：仅请求完成日志；尚未加入 Service 内部日志上下文、错误原因分类、客户端断连日志或日志存储检索系统。日志可定位失败请求，但尚不能单独定位数据库故障根因；本次生产 smoke 已确认部署版本、响应头和 Render 日志字段。
- 实现审查证据：学习者正确指出提前写日志会记录错误状态码；正确预测全局编号会让 A 使用 B 的编号，并解释每次函数调用创建局部编号可避免干扰。
- 迁移回答：学习者答对两次重试 Request ID 不同、Idempotency-Key 相同，并说明是新的请求；幂等键关联同一逻辑操作的排错作用由 Agent 补充。
- 日志检索证据：学习者正确选择 statusCode、durationMs 筛选失败慢请求，并用 Request ID 关联；限定创建接口还需 method 和 route，由 Agent 补充，后续间隔复测。
- 后续间隔复测 Session、幂等键职责及完整日志筛选条件；需要 Agent 补充的部分不算全面独立掌握。

## 当前课：数据库 Readiness

- 唯一目标：数据库不可用时 `/ready` 有界返回 503，资源不因重复探测堆积；`/health` 保持静态存活检查。
- 学习证据：学习者判断 HTTP 可响应不代表数据库连接正常；提出最大等待时长，并正确说明 Promise.race 不取消底层查询、重复探测增加数据库压力。最初选择失败返回 500，503 语义及“HTTP 可响应不证明整个 Service 正常”由 Agent 补充。
- 工程证据：专用 pg 池 max=1、并发共享一次探测；连接等待 1000ms、服务端语句 500ms、客户端查询 750ms，失败连接销毁、成功连接释放复用，应用关闭时结束探测池。
- HTTP 成功返回 200 和 `{ status: 'ok' }`，失败返回 503 和 `{ status: 'not_ready' }`，响应禁止缓存；失败完成日志通过 Request ID 关联安全的 database_probe_failed 分类，不暴露原始数据库错误。
- 实验：本机 mini_saas_test 经测试专属 TCP 代理执行 200 → 503 → 200；握手无响应、已建立连接停止转发时请求均在测试上限内返回，重复并发失败后代理连接清零；真实 pg_sleep 被服务端 statement_timeout 取消。把失败连接改为复用时单元测试失败，恢复后通过。故障操作由 Agent 演示，未作为学习者独立测评。
- 边界：仅证明独立连接可执行 SELECT 1，不检查业务池饱和、表结构、写权限或全部业务能力；连接与查询是两个阶段，预算合计约 1750ms 加调度开销，并非严格实时总截止时间。应用启动仍依赖 TypeORM 建连；本次生产 smoke 的 `/ready` 已返回 200，但没有修改部署平台探测配置。
- 实现审查：学习者能预测复用查询超时的连接会让后续请求超时；`/ready` 为 200 仍不能证明业务创建成功的迁移题暂未作答，已提示其不覆盖连接池、schema、权限、输入与写入/事务。
- Readiness 迁移证据：学习者将 409 Email is already registered 判断为业务规则拒绝，并优先查看请求日志；能指出提示与项目创建不符。Agent 补充日志不记录请求参数，需用 Request ID 核对 method、route、statusCode，再查看浏览器 Network 的实际响应；/ready=200 只能排除本次独立数据库探测失败。
- 已完成：基础 CI。工作流已在 push 与 pull request 触发，使用独立 PostgreSQL 17 服务和 CI 注入的测试环境变量；依次执行锁文件安装、格式、只读 lint、单元测试、migration、HTTP e2e、build 与无重写检查。
- 故障证据：学习者最初选择单元测试；Agent 补充 DTO 校验须由 HTTP e2e 覆盖。临时删除 RegisterDto 的密码最小长度后，/auth/register 短密码用例实际得到 201 而非预期 400，34 项应用 e2e 中 1 项失败；恢复后 34 项重新通过。
- 远端证据：首次 GitHub runner 在 HTTP e2e 阶段发现 readiness e2e 隐式读取本机文件；修复为 CI DATABASE_URL 优先、本地文件回退后，[GitHub Actions run 34202748980](https://github.com/human85/backend-learning/actions/runs/34202748980) 在 59 秒内完整通过。
- 当前边界：它不运行 Hono 会清表的集成测试、前端测试、浏览器/线上验收或自动生产 migration。CI 的测试数据库只用于该 job，不能代替部署验证。
- CI 审查证据：学习者独立说明 migration 先于 e2e 是因为否则数据库仍是旧 schema，测试无法代表当前代码；并说明云端 CI 不能读取本机环境变量。Agent 补充 CI 新库可能为空，migration 负责建立当前 schema（必要时也可包含受控数据迁移）。

- 开发/生产代理差异复测：学习者正确判断开发环境通常没有反向代理，因此不需要设置 `trust proxy`；生产环境的代理信任必须依据真实部署拓扑配置。
- 转发头信任边界复测：学习者正确判断开发环境直连 Nest 时应忽略客户端手动添加的 `X-Forwarded-Proto`；需保留“无受信任代理时忽略”与“生产有代理时按拓扑信任”的条件区别。
- 多层代理拓扑判断复测：学习者正确判断出现 CDN 和反向代理两层时，`trust proxy = 1` 不一定准确，应确认前置代理是否受信任；Agent 补充还需核对代理链、转发头覆盖规则、稳定路径和可信地址范围，不能只按层数机械修改。
- 可变代理路径风险复测：学习者正确判断一层/两层路径混用时固定 `trust proxy = 2` 不安全，可能让攻击者伪造额外代理信息；应固定入口路径或按已知代理地址/网络范围限制信任。
- 部署证据前置条件复测：学习者正确判断缺少公网地址和部署版本证据时不能开始 smoke，因为可能命中错误环境或旧版本；应先确认目标地址、commit 和代理拓扑。
- 前端 API 接入澄清：当前生产前端使用相对基地址 `/api`，Render Static Site 将 `/api/*` Rewrite 到独立 API Service；项目确实存在 API 接入和历史公网部署。此前“没有 API 地址”的说法不准确，当前真正未重新核对的是本轮改动对应的线上 URL/commit 证据。
- 部署证据确认方法补课：已说明从 Render 部署记录核对 commit/服务 URL，从浏览器 Network 核对前端 `/api` Rewrite、Cookie 和受保护接口，从 `/health`/`/ready` 与 Neon 定向查询补齐运行和数据证据；内部 `X-Forwarded-Proto` 通过拓扑配置与 Secure Cookie 行为间接验证。该流程为讲解，未新增独立测评。
- R2 进度核对：Request ID/日志、Readiness、基础 CI 和生产 smoke 四个主目标均有证据；路线图三个工程退出条件已全部满足。最新远端 run 34446818133 已通过；学习掌握度不直接按工程百分比换算，反向代理信任范围仍需间隔复测。
- DELETE 重试复测：学习者判断响应丢失后的同一 DELETE 具备安全、幂等；幂等部分正确，Agent 补充 HTTP safe 与 idempotent 不同。DELETE 会改变状态，因此不是 safe method；当前实现首次返回 204、重复返回 404，但资源最终不存在，状态效果仍幂等。
- 幂等复述证据：学习者独立说明幂等关注最终资源状态，两次 DELETE 后资源都不存在；响应码反映具体请求状态，不必保持相同。该复述准确覆盖状态效果与响应合同的区别。
