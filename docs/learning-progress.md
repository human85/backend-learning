## 下一课：R2 第一课——Request ID 与结构化日志

唯一主目标：让一次请求的 ID 能贯穿 HTTP 响应和结构化日志，支持从错误日志回到具体请求。

- 位置：`HTTP request → Request ID middleware/interceptor → Controller/Service → logger → HTTP response/error`。
- 先由学习者预测 Request ID 应在哪里生成或透传、响应如何暴露、日志必须包含哪些关联字段以及哪些敏感值不能记录；Agent 等待回答后再实现。
- 工程验收：成功和异常请求都能在响应与日志中关联；没有客户端 ID 时服务端能生成安全 ID；日志不记录密码、Cookie、Token 或数据库连接密钥。
- 学习验收：学习者能区分 Request ID、Session 身份和业务实体 ID，并说明结构化日志相比拼接字符串解决了什么排错问题。
- 本课不同时实现指标、告警、Readiness 或登录限流。
