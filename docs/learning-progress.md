## 下一课：证明 Outbox 写入失败会整体回滚

唯一主目标：用可重复实验验证项目、Outbox 和幂等记录共享同一事务的边界。

- 位置：`POST /projects → 项目创建 / 幂等编排 → transaction → Projects / Outbox / Idempotency Repository → PostgreSQL`。
- 先由学习者预测中途失败时会留下哪些数据、相同 key 重试会发生什么；Agent 等待回答后再讲解和展示结果。
- Agent 在隔离测试数据库中制造 Outbox 写入失败，保留真实事务和项目插入；不能仅 mock 整个事务来证明数据库回滚。
- 工程验收：普通与带 key 创建都不留下本次项目或事件；带 key 路径不留下本次 reservation；移除故障后同 key 可成功创建一次。验证业务行和响应，不要求序列 ID 连续。
- 学习验收：学习者用自己的话解释结果，再判断一个改变故障位置的场景；没有回答时保持“待验证”。
- 本课范围到此为止。Worker、队列、Redis 和幂等记录清理不与本课一起实现。
