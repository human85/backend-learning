## 下一课：实现最小单 Worker 处理 pending Outbox

唯一主目标：在事务提交后由单 Worker 读取并处理 pending 事件，区分成功确认与失败重试。

- 位置：`pending outbox_events → Worker 领取/处理 → 模拟接收端 → 成功确认或失败重试`。
- 先由学习者回忆事务回滚与响应丢失的区别，再预测 Worker 成功和失败后数据库状态；Agent 等待回答后再讲解和实现。
- 工程验收：单 Worker 能处理一条 pending 事件并标记成功；临时失败保留错误、增加 attempts 并按规则再次可处理；重启后仍能继续处理未完成事件。
- 学习验收：学习者能解释“数据库提交”和“外部接收端成功”不是同一件事，并判断 Worker 在确认前崩溃时为什么可能重复投递。
- 本课范围不引入 Redis、队列框架、多 Worker 领取锁、真实邮件/支付或新的任务查询 API。
