# 学习档案说明

`docs/` 用于保存学习目标、当前进度、历史过程和已经形成的知识。它让项目在被 Git clone 到其他设备后，新 Agent 不依赖旧对话也能继续担任后端导师。

## 文档结构

| 路径                       | 职责                           | 更新时机               |
| -------------------------- | ------------------------------ | ---------------------- |
| `learning-progress.md`     | 当前学习状态的唯一快照         | 每次课程或练习结束后   |
| `learning-method.md`       | 课程流程、证据标准与复测方法   | 教学方式调整时         |
| `knowledge-history.md`     | 截至 2026-09-02 的历史知识表   | 仅作历史查阅，不扩充   |
| `roadmap.md`               | 后端学习路线和阶段状态         | 阶段开始、完成或调整时 |
| `learning-log.md`          | 按时间追加的学习记录           | 每次发生有效学习后     |
| `decisions.md`             | 长期有效的教学与技术决策       | 作出重要取舍时         |
| `30-day-fullstack-loop.md` | 第一轮 30 天全栈闭环计划       | 里程碑或范围调整时     |
| `projects/`                | 各完整项目的目标、状态和下一步 | 项目状态变化时         |
| `notes/`                   | 按主题整理的可复习知识         | 形成可复用知识时       |

## 新会话读取顺序

先阅读 [learning-progress.md](learning-progress.md)，再读取其中当前焦点对应的 `projects/*.md`，然后查看 [learning-log.md](learning-log.md) 的最新记录和 [roadmap.md](roadmap.md) 的当前阶段。安排课程前读取 [learning-method.md](learning-method.md)；历史知识表、专题笔记和决策只在相关时读取。最后检查实际代码和 Git 状态，避免仅凭文档假设项目现状。

## 维护规则

- `learning-progress.md` 只保留当前事实、焦点能力的工程/学习证据、下一课和复测项；旧知识表已迁入 `knowledge-history.md`，不在新会话默认全文加载。
- `learning-log.md` 只追加记录，不修改旧结论；后续理解有变化时新增一条记录。
- 使用 `YYYY-MM-DD` 日期，分别记录工程验证边界和学习者回答、提示程度；等级定义以 `learning-method.md` 为准，历史“接触过 / 理解中”不自动升级。
- 项目档案保存实现状态，路线图保存阶段范围，学习方法保存教学规则；具体下一课仅以当前进度为准，其余文档链接引用，避免多个“下一步”互相漂移。
- 纯文档维护单独标明“没有新增课程或能力测评”；历史测试与部署证据不能写成此次重新验证。
- 不记录对恢复学习无帮助的聊天内容、工具过程或大段代码副本。
- 课程代码、测试和对应的文档更新应尽量进入同一次提交。
- 一个学习阶段形成完整、可验证的结果后，由 Agent 主动创建 Git 提交并正常推送当前分支，保持多设备学习进度同步；不得改写历史或强制推送。
