# 接受邀请：事务回调中的分支练习

本实验只检查 JavaScript 控制流，不连接数据库，也不是可部署的邀请功能。`manager` 是测试提供的假对象，方法形状用于衔接此前的 TypeORM 讲解；测试通过不证明 SQL、约束、事务回滚或并发正确。

## 动手范围

原练习要求只修改 `accept-invitation.cjs` 的 TODO 位置（现已完成）。目标是只有影响行数恰好为 1 才继续插入成员；其他结果抛出 `Error`，消息为 `邀请无法接受`。

不要改测试，不要把成员插入删掉，也不要提前 return 来代替抛出异常。暂时不需要引入 Entity、DTO、数据库连接或依赖。

在仓库根目录运行：

```bash
node --test labs/invitation-transaction/accept-invitation.test.cjs
```

起始骨架有 2 个通过、2 个失败；2026-11-12 学习者补完后，4 个用例全部通过。测试同时要求 0 和无法确定影响行数时都停止，插入失败时错误继续向外传播。

## 骨架中的位置

`dataSource.transaction()` 提供回调中的 `manager`；更新和插入都通过它执行。真实 TypeORM 会在回调成功时提交、抛错时回滚，但这里的假对象仅执行回调，不实现数据库事务。

`projectId` 在练习中是可信固定输入。真实实现必须从当前邀请记录获取项目归属，用户身份来自 Session；还需数据库唯一约束和实际事务验证。

本练习已完成，仍不纳入应用默认测试与 CI；测试通过仅证明这里覆盖的控制流。
